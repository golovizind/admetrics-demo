# Локальный запуск

Всё работает из одной папки, без Docker и без внешних сервисов. База по
умолчанию — файл SQLite рядом; Postgres нужен только когда захотите.

## 1. Зависимости

```bash
cd admetrics
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## 2. Настройки

```bash
cp .env.example .env
```

Заполнить три обязательных поля:

**`ADMETRICS_KEY`** — ключ шифрования мультитокенов:

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

**`TELEGRAM_BOT_TOKEN`** — у @BotFather: `/newbot`, дальше по подсказкам.

**`ADMIN_TG_IDS`** — ваш числовой Telegram ID. Узнать: напишите @userinfobot.
Без него админских кнопок не будет ни у кого — бот не сможет отличить вас
от постороннего.

Подхватить переменные в текущей сессии:

```bash
set -a && source .env && set +a
```

## 3. Проверка, что всё цело

```bash
python3 test_core.py && python3 test_app.py && python3 test_probe.py
```

Три набора, 302 проверки. Если что-то красное — дальше идти не стоит.

## 4. Первый запуск

```bash
python3 manage.py init          # создать схему
python3 bot.py                  # запустить бота
```

Бот напишет, какой код исполняет, под каким именем поднялся и кого считает
админом. Дальше — в Telegram: напишите ему что угодно, хоть «привет», и
откроется главный экран.

**Команд в боте нет.** Всё делается кнопками: разделы, страницы списков,
переключение периода, назначение владельца кабинета, включение и отзыв личек,
запуск сбора. Любое присланное сообщение бот понимает как «покажи меню» —
ошибиться в синтаксисе невозможно, потому что синтаксиса нет.

Порядок первого заведения:

1. **Маркетологи → ➕ Добавить маркетолога** — бот попросит имя одним
   сообщением и сразу вернёт ссылку-приглашение.
2. **Перешлите ссылку человеку.** Он открывает её, жмёт «Начать» — и привязан.
   Ни кода, ни команд набирать не нужно.
3. **Карточка маркетолога → ➕ Добавить личку** — бот попросит мультитокен
   (можно с прокси через пробел).
4. **🔄 Собрать сейчас** — или подождать очередной цикл.
5. **Кабинеты → кабинет → 👤 Сменить владельца** — закрепить кабинет за
   маркетологом.

Текст человек набирает ровно дважды: имя нового маркетолога и мультитокен.
Кнопкой ни то ни другое не выражается, поэтому оба раза бот спрашивает сам,
и рядом есть «Отмена».

**Сообщение с мультитокеном бот удаляет из чата** сразу после сохранения,
чтобы секрет не остался в истории переписки.

## 5. Курсы валют

Витрина считает в рублях, поэтому по каждой валюте кабинетов нужен курс:

```bash
python3 manage.py fx set 2026-08-12 USD 80.5
python3 manage.py fx fill USD 2026-08-01 2026-08-31   # растянуть на период
```

Без курса суммы **не занижаются нулём** — они попадают в предупреждение
«нет курса» и не входят в итог. Это намеренно: молчаливое занижение хуже
явной дырки.

## 6. Что происходит само

Бот раз в `BOT_CYCLE_MINUTES` (по умолчанию 10) запускает сбор и рассылает
накопившиеся алерты. Отдельный cron не нужен — процесс бота делает и то и другое.

Алерты идут владельцу кабинета и копией админам: бан с расшифровкой причины,
срез или подъём дневного лимита, смена карты, реджект объявления с текстом,
мёртвая личка, расхождение с картами выше порога. Каждый алерт дедуплицируется
— один бан приходит один раз, а не каждые 10 минут.

## 7. Разведка мультитокена

Прежде чем заводить личку, полезно посмотреть, что этот токен вообще отдаёт —
набор полей зависит от приложения и уровня доверия аккаунта:

```bash
python3 probe.py --session "<контейнер FBTOOL>" --proxy socks5://… --max-accounts 10
```

Шаг 8 отдельно проверяет цепочку доступа к комментариям: отдают ли страницы
page-токен и есть ли право на модерацию. Скрипт только читает.

## 8. Веб (необязательно)

Тот же набор данных, но страницами:

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

`/admin` — администрирование, `/` — витрина, `/login` → `/me` — кабинет
маркетолога.

## «Я перезапустил, а изменений нет»

Почти всегда отвечает не тот файл, который вы правили: рядом живёт вторая копия
проекта или не убит прежний процесс. Два бота на одном токене дерутся за
`getUpdates`, и отвечает тот, кто успел первым — то есть старый.

```bash
ps aux | grep bot.py | grep -v grep   # видно путь каждого запущенного бота
pkill -f bot.py                       # убить все
cd ~/Downloads/admetrics && python3 bot.py
```

При старте бот печатает, какие файлы исполняет и когда они правились. Дата
сборки видна и в шапке главного экрана, полные пути — в разделе «Состояние».
Если дата старая или путь не из этой папки — вы запустили не то.

## Если что-то пошло не так

```bash
python3 manage.py check      # проверки целостности данных
python3 manage.py report     # витрина в терминале
```

`check` ловит то, что ломается молча: пересечение интервалов владения
(завышает спенд), кабинеты со спендом без владельца, дырки в курсах,
личики, требующие переподключения.

## Чего пока нет

**Коллектора MyBroCards.** Таблица `card_payments`, вся логика сверки и
пороги готовы и покрыты тестами, но наполнять их живыми данными нечем: нужен
API-ключ и базовый URL их REST. Пока таблица пуста, «Сверка» покажет нули.

**Модерации комментариев.** Ждём результата `probe.py` на живом токене —
без него неизвестно, отдаёт ли приложение FBTOOL право
`pages_manage_engagement`.
