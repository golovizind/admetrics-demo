# Admetrics API

Только чтение. Отдаёт то, что Admetrics собрал из Facebook и MyBroCards,
плоскими строками — чтобы принимающая сторона не разбирала вложенность.

Актуально на 16.09.2026.

## Доступ

Базовый адрес: `https://admetrics.example.com/api/v1/`

Ключ передаётся **только заголовком**:

```
Authorization: Bearer <ключ>
```

В query-параметре ключ не принимается намеренно: адрес попадает в логи
прокси, в историю браузера и в `Referer`, а работает оттуда так же, как из
заголовка.

Ключи выпускаются в портале: «Ещё» → «Ключи API». Ключ показывается **один
раз**, при выпуске. Хранить его, чтобы посмотреть потом, значит завести
второе место, откуда он утечёт; потерявший выпускает новый.

Ключ можно выпустить **на конкретного маркетолога** — тогда он видит только
его кабинеты. Ключ без маркетолога видит всё. Первое — чтобы отдать
подрядчику ровно его кусок, второе — для выгрузки всей команды.

## Общие правила

**Даты обязательны и явны** — во всех ручках, кроме `/links`. Формат
`YYYY-MM-DD`. Умолчания вроде «за сегодня» опаснее отказа: забывший даты
получил бы один день, принял его за весь период и не заметил.

**Страницы.** `limit` (по умолчанию 1000, максимум 5000) и `offset`. Если в
ответе есть `next_offset` — данные не кончились, повторите с ним. Когда
`next_offset` равен `null`, это последняя страница.

**Ошибки.** Поле `error` с текстом на русском. Коды: `401` — ключ не принят,
`404` — неизвестная ручка, `400` — не сошлись параметры.

## `GET /accounts`

Реестр рекламных кабинетов — чтобы `act_id` из остальных ручек имел имя.
Дат не требует.

`act_id`, `name`, `status`, `status_label`, `disable_label`, `currency`,
`bm_id`, `daily_spend_limit`, `spend_cap`, `balance`, `amount_spent`,
`funding_last4`, `next_bill_date`, `timezone`, `owner_id`.

## `GET /spend`

Открут по дням. Параметр `level`: `account` (по умолчанию) или `campaign`.
Складывать уровни между собой нельзя — это одни и те же деньги с разной
детализацией.

Общие поля: `date`, `act_id`, `currency`, `spend`, `impressions`, `clicks`,
`link_clicks`, `leads`, `purchases`, `revenue`. При `level=campaign`
добавляются `campaign_id` и `campaign_name`.

Необязательный `act_id` — список кабинетов через запятую.

> `leads`, `purchases` и `revenue` приходят из Meta, то есть из пикселя.
> Это оценка по событиям, а не деньги. Настоящая выручка живёт в трекере.

## `GET /transactions`

Фактические списания Facebook. Не insights: insights оценивает по показам, а
здесь деньги, которые реально сняли.

`tx_id`, `act_id`, `time`, `amount`, `currency`, `tax_amount`,
`charge_type`, `status`, `payment_option`.

## `GET /payments`

Платежи с карт MyBroCards.

`payment_id`, `date`, `date_final`, `amount`, `fee`, `currency`, `state`,
`decline`, `card_last4`, `card_bin`, `card_title`, `merchant`, `descriptor`,
`team`, `marketer_id`, `user_email`.

Владение здесь проверяется по самой строке платежа: у неё свой
`marketer_id`, а кабинета может не быть вовсе — карта могла платить за
что-то ещё.

## `GET /links`

Связка с Keitaro: **id кампании трекера, ссылка, расход**. Три поля, больше
ничего — это выгрузка для сведения с выручкой, и лишние колонки в ней
мешают.

`keitaro_id`, `link`, `spend`.

**Даты необязательны** — единственная такая ручка. Без них считается весь
открут, что есть в базе: кампания трекера живёт дольше отчётного окна, и
«сколько на неё ушло всего» спрашивают чаще, чем «сколько за неделю».
С `since` и `until` выборка сужается.

**Ссылка отдаётся без параметров** — только схема, хост и путь. Параметры
выбрасываются целиком по двум причинам. Там одни макросы вида `{{ad.id}}`,
которые до клика ничего не значат. И среди них ездит `fbtoken` — рабочий
токен Facebook; таскать его в отчёты, файлы и переписку незачем.

Один и тот же адрес с разным набором макросов схлопывается в одну строку.

Попадают только объявления, которые **могут откручиваться** (`ACTIVE`,
`WITH_ISSUES`) и у которых **связь с трекером найдена**. Остановленное
объявление выручки уже не принесёт, несопоставленное принесёт её мимо нас —
в обоих случаях строка испортила бы расчёт молча.

`spend` — расход из кабинета Facebook, округлённый до копеек.

Необязательный `act_id` — список кабинетов через запятую.

## Примеры

```bash
# Реестр кабинетов
curl -H "Authorization: Bearer $KEY" \
  https://admetrics.example.com/api/v1/accounts

# Открут по кампаниям за неделю
curl -H "Authorization: Bearer $KEY" \
  "https://admetrics.example.com/api/v1/spend?level=campaign&since=2026-09-09&until=2026-09-16"

# Связка с трекером — за всё время, без дат
curl -H "Authorization: Bearer $KEY" \
  https://admetrics.example.com/api/v1/links
```

Ответ `/links`:

```json
{
  "since": "все данные",
  "until": "все данные",
  "count": 2,
  "next_offset": null,
  "rows": [
    {"keitaro_id": 141, "link": "https://offer-one.example/", "spend": 4662.54},
    {"keitaro_id": 162, "link": "https://offer-two.example/", "spend": 1830.11}
  ]
}
```

## Выгрузка без API

Те же три колонки можно скачать руками: портал → «Аккаунты» → «Выгрузка для
сверки с Keitaro». CSV с разделителем `;` и BOM — Excel с русской локалью
иначе кладёт строку в одну ячейку. Всегда за всё время, независимо от
периода на экране.

## Чего в API нет

**Выручки и конверсий.** Они на стороне Keitaro. `/links` даёт ключ, по
которому их подставляют: `keitaro_id`.

**Управления.** Ключ умеет только читать. Ключ, способный останавливать
кампании, — это чужие деньги в чужом файле конфигурации.
